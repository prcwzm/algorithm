# 交易系统知识路线

本路线面向证券、数字资产和支付类交易平台，按“业务生命周期 → 核心子系统 → 分布式可靠性 → 高性能工程”的顺序学习。

## 一、金融与交易基础

- 交易品种：股票、债券、期货、期权、外汇、数字资产
- 参与角色：买方、卖方、经纪商、交易所、清算机构、托管机构
- 订单类型：限价单、市价单、止损单、撤单、改单
- 交易概念：价格、数量、成交额、手续费、保证金、涨跌停、交易时段
- 账户概念：余额、可用余额、冻结余额、持仓、可卖数量

## 二、数据结构与算法

- 哈希表、队列、堆、栈
- 红黑树、跳表、B+ 树
- 优先队列与订单簿
- 排序、二分、滑动窗口
- 并发编程与线程安全
- 时间复杂度、空间复杂度和内存访问效率

## 三、交易主流程

```text
行情接入 → 用户/账户校验 → 订单创建 → 参数校验 → 风控检查
→ 资金/持仓冻结 → 订单路由 → 撮合成交 → 成交回报
→ 资金/持仓更新 → 清算结算 → 对账与报表
```

重点梳理订单创建、修改、撤销、部分成交、完全成交、拒单、超时、网络重试和日终批处理。

FIX 标准将订单处理、行情、交易报告和交易后处理划分为不同业务领域，可作为订单生命周期和消息设计的行业参考：

- [FIX Trading Community 官方 GitHub](https://github.com/FIXTradingCommunity)
- [FIX Orchestra 官方实现与示例](https://github.com/FIXTradingCommunity/fix-orchestra)

## 四、订单状态机

```text
Created → PendingRiskCheck → Accepted → New
                                    ├→ PartiallyFilled → Filled
                                    ├→ Canceled
                                    └→ Expired
                         └→ Rejected
```

需要明确每个状态的进入条件、合法转换、终态、重复执行行为，以及成交和撤单并发时的处理规则。

FIX Orchestra 对订单状态和合法状态转换有详细说明，例如已撤销订单不能再次转为成交状态：[FIX Orchestra 官方仓库](https://github.com/FIXTradingCommunity/fix-orchestra)。

## 五、核心子系统

### 1. 用户与账户

- 用户、机构、交易账户和权限
- 多币种账户
- 资金账户与证券账户
- 余额、冻结金额、持仓和可用数量

### 2. 订单管理系统（OMS）

- 订单接收、校验和状态管理
- 订单拆分、合并和路由
- 撤单、改单和成交回报
- 订单查询、审计和历史记录

### 3. 风控系统

- 余额和持仓检查
- 价格、数量、频率和累计限额
- 自成交保护
- 黑名单、账户状态和市场状态检查
- 交易前风控必须位于撮合系统之前

### 4. 撮合引擎

- 价格优先、时间优先
- 买卖订单簿维护
- 限价单、市价单和部分成交
- 撤单、自成交保护和成交广播
- 撮合状态恢复与结果重放

### 5. 行情系统

- 快照行情、增量行情和成交行情
- 订单簿深度、序列号和乱序处理
- 丢包补齐、行情重放和多级缓存

FIX 官方 GitHub 组织提供协议、行情和交易相关的标准实现与资料：[FIX Trading Community](https://github.com/FIXTradingCommunity)。

### 6. 清算与结算

- 撮合：买卖双方匹配
- 清算：计算应收应付、手续费和净额
- 结算：完成资金和资产交割
- T+0、T+1、净额清算、全额清算
- 失败结算和日终批处理

支付系统、结算最终性和安全机制可参考 BIS 资料：[Payment and Settlement](https://www.bis.org/publ/cpss34ep2.pdf)。

### 7. 对账与审计

- 订单、成交、资金和持仓流水
- 外部渠道账单和日终对账
- 差异检测、修复和审计追踪
- 通过流水重算余额，避免只依赖当前余额

## 六、分布式系统与一致性

重点掌握：

- 幂等键、唯一约束、乐观锁、悲观锁、MVCC
- 事务隔离级别
- Outbox、可靠消息和消息幂等
- 消息顺序、重复消费和最终一致性
- Saga、TCC、状态机和事件溯源
- 快照、事件重放和故障恢复

典型场景：订单成功但响应丢失、重复提交、扣款成功但回报丢失、成交成功但持仓更新失败。通用处理方式是“唯一请求号 + 状态查询 + 幂等处理 + 重试 + 补偿”。

## 七、高性能与低延迟

- 内存撮合和单线程状态机
- 无锁队列、对象池、Ring Buffer
- 批量处理、顺序写日志和 mmap
- CPU Cache、False Sharing、NUMA
- GC 调优、网络 IO 和二进制协议

FIX Session 层可用于学习有序消息、序列号、断线重连和状态恢复：[FIXP Specification](https://github.com/FIXTradingCommunity/fixp-specification)。

## 八、可靠性、容灾与安全

- 主备切换、双活、多副本和机房容灾
- 断线重连、消息重放、快照恢复
- 交易暂停、限流、熔断和降级
- 灾备演练、数据校验和故障复盘
- 身份认证、权限控制、敏感数据保护和审计
- 监管报送、反洗钱、客户身份识别和交易留痕

## 九、实践项目路线

1. **单机订单系统**：订单创建、撤销、查询、状态机和内存账户。
2. **简易撮合引擎**：买卖订单簿、价格时间优先、部分成交和成交回报。
3. **持久化与幂等**：数据库事务、唯一订单号、资金冻结和重复请求处理。
4. **消息驱动架构**：订单事件、成交事件、资金事件、重试队列和死信队列。
5. **清算结算与对账**：手续费、持仓变更、日终清算、外部账单和差异修复。
6. **性能与容灾**：内存撮合、事件重放、快照、主备切换、压测和延迟监控。

## 十、推荐学习顺序

```text
金融基础
→ 订单生命周期
→ 订单状态机
→ 账户与资金冻结
→ 风控
→ OMS
→ 撮合引擎
→ 行情系统
→ 清算结算
→ 对账审计
→ 分布式一致性
→ 高性能
→ 容灾与合规
```
